# ADR-0001: バックエンドの初期技術選定(ビルドツール・Javaバージョン・Lombok不使用)

- 日付: 2026-08-12
- ステータス: 承認済み

## コンテキスト

T1(開発環境構築)でSpring Bootプロジェクトを新規作成するにあたり、ビルドツール・Javaバージョン・補助ライブラリ(Lombok)を初期選定する必要があった。[02_requirements.md](../02_requirements.md)にある通り、このプロジェクトはアプリの完成よりも「設計・実装を学ぶこと」を優先事項としているため、選定基準にも学習のしやすさを含める。

## 検討した選択肢

### ビルドツール
1. **Maven** — XMLベースの設定ファイル(`pom.xml`)。記述は冗長だが、何が設定されているかがそのまま見える
2. **Gradle** — Groovy/Kotlin DSLベース。記述は簡潔だが、DSLの裏側の挙動(タスクの依存関係など)を理解するのに追加の学習が要る

### Javaバージョン
1. **Java 17(LTS)** — Spring Boot 3系の最小要件
2. **Java 21(LTS)** — 直近の最新LTS版

### Lombok(getter/setter等を自動生成するライブラリ)
1. **導入する** — ボイラープレートコードを削減できる。実務でも広く使われる
2. **導入しない** — Javaのクラスがgetter/setter等を含めてどう動いているかを、素のコードで理解できる

## 決定

- ビルドツール: **Maven**
- Javaバージョン: **Java 21(LTS)**
- Lombok: **導入しない**

## 却下した理由・トレードオフ

- **Gradleを選ばなかった理由**: 学習段階では、設定ファイルに何が書いてあるかを素直に読める方が理解の助けになる。Gradleの簡潔さは、Spring Bootの仕組み自体にある程度慣れてから活きると判断した
- **Java 17ではなく21を選んだ理由**: Spring Boot 3系の要件を満たす中で最新のLTS版を使い、当面バージョンアップを気にせず学習に集中するため
- **Lombokを導入しないトレードオフ**: getter/setter等を手書きする分、コード量は増える。実務でLombokを使う場面に備え、素のJavaの挙動に慣れた後で導入を検討する

## 影響

- `backend/pom.xml`で依存関係を管理する(Gradleのbuild.gradleは使わない)
- エンティティ・DTOクラスのgetter/setter/コンストラクタは手書きする
- 将来Lombokを導入する場合は、既存クラスへの適用要否を別途判断する
