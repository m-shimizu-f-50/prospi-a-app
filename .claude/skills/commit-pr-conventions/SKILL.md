# コミット & PR 作法

## コミットメッセージ

Conventional Commits形式で書く。

```
<type>(<scope>): <summary>

<body（任意・必要な場合のみ）>
```

- type は以下のいずれかを使う: feat, fix, refactor, docs, test, chore, style, perf
- summary は日本語で50文字以内、命令形（「〜する」「〜を修正」）で書く
- 複数の変更が混ざっている場合は、コミットを分けるようユーザーに提案する
- bodyは「なぜこの変更が必要か」を書く。「何をしたか」はdiffを見れば分かるので繰り返さない

例:

```
fix(auth): トークン期限切れ時のリダイレクトループを修正

期限切れチェックがログイン後にも実行されており、
無限リダイレクトが発生していたため、チェック対象から除外した。
```

## PR説明文

**対象コミットの範囲**: `main`からの累積差分ではなく、`.claude/pr-checkpoint.txt`に記録された前回のチェックポイント（コミットハッシュ）から`HEAD`までの差分のみを対象にする。

- `.claude/pr-checkpoint.txt`が存在しない、またはそこに記録されたコミットが現在のブランチの祖先でない場合は、`git merge-base main HEAD`（ブランチがmainから分岐した地点）を起点にする
- PR説明文を作成したら、`.claude/pr-checkpoint.txt`の内容を現在の`HEAD`のコミットハッシュに更新する（次回はここが新しい起点になる）
- 「PRを作成する」だけでなく「PR説明文を書いて/更新して」と頼まれた時点でチェックポイントを更新する（実際にPRを出したかどうかは問わない）

以下のテンプレートで書く。

```markdown
## 概要

(このPRが何をするものか、1〜2文で)

## 変更内容

- 変更点を箇条書きで

## 動作確認

- 確認した手順・テスト内容

## 補足

(レビュアーに伝えたい注意点があれば)
```

- 「概要」は非エンジニアが読んでも分かるレベルの平易さにする
- スクリーンショットが有用な変更（UI変更など）は「動作確認」にスクリーンショット添付を促す文言を入れる
- breaking changeがある場合は「補足」に必ず明記する
